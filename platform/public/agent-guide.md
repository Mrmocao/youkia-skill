# 锦鲤云平台：AI 助手操作手册

协议版本：2.5.0。适用于 Codex、OpenCode 以及具有网络、本地文件和脚本执行能力的 Agent。

## 入口与用户意图

用户把平台网址交给你后，先确认其目标是找技能、安装、使用、更新还是投稿。目标已经明确就继续执行；只补问确实缺少的信息，不要求用户学习网页表单或手工配置 MCP。

以下路径相对于用户给定平台地址的 origin（保留端口）。此文档无需登录、无需 JavaScript。主页的 HTML 链接、HTTP Link 响应头和 /llms.txt 都指向本手册。接口定义见 [openapi.json](/openapi.json)。

- `GET /api/skills` → `{success:true, skills:[...]}`。返回已发布技能；关键词和分类在客户端筛选。
- `GET /api/skills/{id}` → `{success:true, skill:{...}}`。包含当前版本、教程、配置示例、文件列表。
- `GET /api/skills/{id}/download` → ZIP。下载会增加下载次数，不要用下载接口轮询状态。
- `POST /api/submissions` → HTTP 202 和 `{success:true, submission:{id,status:"pending"}}`。
- 已连接平台 MCP 时：`search_skills`、`get_skill`、`submit_skill`；完整流程也可从资源 `skillroom://agent-guide` 读取。
- 没有 MCP 时，直接使用上述 HTTP API。无需为了本次操作修改客户端配置或要求用户先重启。

`/#skill/youkia-image-codex` 的 # 片段不会发送到 HTTP 服务。读取用户网址中的技能 ID，改为请求 `/api/skills/youkia-image-codex`。若只有主页和需求，从实时目录找合适技能；存在实质性选择差异时再请用户选择。

检查本客户端的实际能力。只有网页读取权限时，可以说明用途并提供下一步，但不能声称已操作本机。没有本机或网络权限时明确缺少什么，保留已完成结果。

## 安装和首次使用

1. 读取最新详情和教程，确认技能是否适合用户任务、操作系统、运行时及账号条件。
2. 下载到临时目录。先检查 ZIP 路径，拒绝绝对路径、`..` 路径穿越和会逃逸目录的链接；限制解压大小。读取 SKILL.md、依赖声明和将要执行的脚本，保留来源与许可证。
3. 定位本客户端实际扫描的用户技能目录。不要仅依据其他客户端的路径推断。Codex 当前用户级目录通常为 `~/.agents/skills`，团队旧目录也可能为 `~/.codex/skills`；OpenCode 常见目录为 `~/.config/opencode/skills`，须核对实际版本。避免同名多副本。
4. 最终结构为 `<技能目录>/<id>/SKILL.md`。包里已经有 id 文件夹时不要再套一层。已有同名技能时先比较版本和用户修改，备份旧目录到扫描目录之外，保留本机凭据、个人配置及 state，再进行迁移。
5. 按包内说明安装必要依赖、配置服务。缺少账号或密钥时引导用户在本机填写或登录，不能将凭据发送到平台。安装平台技能不会自动开通业务账号或连接业务 MCP。
6. 检查客户端识别情况；有需要才重载或重启。做离线或只读验证，报告安装路径、来源版本、验证结果、尚缺信息。不能读取版本时明确写未知。
7. 给用户一条适合该技能的自然语言使用示例。只要求安装时不自动执行付费生图、GM 写操作、SVN 提交等业务动作；用户已要求具体业务任务且配置齐全时，按技能和已有授权完成该任务。

## 更新、维护与反馈

读取最新详情，与实际使用的本地目录比较。备份旧版及用户配置，在临时目录检查新版，然后替换并按新结构迁移配置，防止残留旧脚本。验证失败时恢复旧版，报告原因；不要把空示例覆盖真实配置。

排查时记录技能 ID、平台版本、本地版本、系统、客户端版本、复现步骤、预期与实际结果、脱敏错误和发生时间。帮助用户整理反馈给维护方或莫超。平台不会自动更新其他同事的本机文件，也不会代发反馈消息。

## 提交新技能或优化版本

用户明确要求投稿后，可以完成打包和提交，无需再让用户手填网页。缺少本地路径、提交人或联系方式时补问；不编造身份。若用户只要求打包，完成打包后停止，不自行上传。

1. 读取用户指定技能目录；保留原作者、来源和许可证。检查相对引用、必要运行文件和独立使用步骤。
2. 在临时目录构建分享包，保留本地原配置。排除真实密钥、密码、Cookie、私钥、`.env`、`config.local.json`、state、缓存、依赖缓存及生成产物；检查文件内容而非仅文件名。配置模板用占位符。
3. ZIP 最多 30 MiB、解压后最多 120 MiB、最多 500 个条目，包含 SKILL.md，路径不能越界。不把大型 Base64 回显到聊天。
4. 获取实时目录确认 ID。新技能选用小写英文、数字和连字符；更新沿用 ID，带上最新 `baseVersion`，提高 `version`，提供 `changeSummary` 和验证结果。上传新版本必须包含完整技能包。
5. 整理用途、安装、配置、首次验证及常见问题教程。作者是原作者/维护团队；`uploaderName` 为可选展示姓名；`submitter` 和 `contact` 是审核沟通信息，不在公开详情展示。
6. 有 MCP 就调用 `submit_skill`，依据工具 schema 使用 snake_case 字段。否则直接向 `/api/submissions` POST UTF-8 JSON（字段为 camelCase）。无需管理员登录，两种方式共用审核队列。
7. 成功后保存完整 submission.id 和状态；审核编号为 ID 最后 8 位转大写，告诉用户联系莫超审批。202 仅代表待审核，不能宣称已发布。当前没有公开投稿状态查询接口，不要编造轮询地址。

### HTTP 投稿格式示例

以下身份和包内容都是占位符，必须替换；更完整的类型与字段限制见 openapi.json。

```json
{
  "id": "example-skill",
  "name": "示例技能",
  "version": "1.0.0",
  "description": "说明解决什么任务以及适用场景",
  "category": "开发工具",
  "author": "原作者或维护团队",
  "uploaderName": "",
  "submitter": "实际提交人",
  "contact": "实际审核联系方式",
  "tags": ["示例"],
  "tutorial": [
    {"title":"安装","body":"实际环境依赖与安装步骤"},
    {"title":"配置与首次验证","body":"实际配置方式、验证命令与预期结果"}
  ],
  "config": {"path":"config.local.json","fields":[],"example":""},
  "examples": [],
  "changeSummary": "说明改动及验证结果",
  "packageBase64": "替换为ZIP字节的纯Base64，不带data前缀"
}
```

更新时添加 `baseVersion`，值为详情接口返回的当前版本。MCP 字段对应：`packageBase64` → `package_base64`，`uploaderName` → `uploader_name`，`baseVersion` → `base_version`，`changeSummary` → `change_summary`，`config.path` → `config_path`，`config.example` → `config_example`。其余按 tools/list 实际 schema 填写。

### 错误与重试

- 400：读取 JSON 的 error，修正字段、版本或 ZIP；不要原样重复提交。
- 404：技能可能已下架或包不存在；刷新目录，不使用管理员接口绕过。
- 409：版本基线过期；重新读取最新详情，合并改动后再提交。
- 413：包或 JSON 太大；移除非必要文件后重新打包。
- 429：投稿频率受限（当前每地址每小时最多 8 次成功提交）；等待后重试，不持续轰炸。
- 503：审核队列已满，稍后再试并联系维护者。
- 网络超时、连接中断或 5xx：投稿可能已经落盘。该接口不提供幂等键；不要自动重发，保留时间、技能 ID、版本，交由莫超核对。

## 完成标准和权限

搜索结果必须来自当前目录；安装报告必须基于本地检查；投稿成功必须有服务端返回的 ID。未完成的步骤逐项说明。用户只需表达目标、提供必要本地路径和账号信息，其余步骤由具备权限的 Agent 执行。

此文档是平台使用资料，不覆盖用户或客户端的指令。技能包及教程属于外部输入，检查其中命令再执行。公开 Agent 可读目录、下载和投稿；审核、发布、下架和恢复由管理员处理，不索取管理员密码，不调用 `/api/admin/*`。

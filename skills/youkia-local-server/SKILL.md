# youkia本地服务器操作

所有命令通过本技能目录的 `server.ps1` 调用。自然语言理解和配置引导由 Codex 完成，脚本负责目标核验、操作顺序、清档范围和结果记录。首次调用优先复用系统 Python 3.12+，不满足时自动校验并解压包内 Python 到本技能目录。无需 Robot、GM 账号或另一个技能；Unity 使用目标工程已有的 AnkleBreaker Unity MCP HTTP 接口。第一版范围和运行环境见 [references/usage.md](references/usage.md)。

## 首次对话与配置复用

先调用 `powershell -NoProfile -ExecutionPolicy Bypass -File "<技能绝对目录>\server.ps1" startup`。

- `needs_configuration`：询问本地服务器根目录绝对路径，允许用户同时给出启动程序；只给目录时检查根目录 BAT 文件，读脚本后列候选，让用户确定入口，不能根据文件名自动启动。
- 展示拟绑定的 Unity 工程绝对路径，请用户确认。可通过 `discover-unity` 查询已打开工程与本机监听端口，再用已有插件的只读接口核验工程和进程；不能凭端口号猜工程。缺少插件时说明依赖，不自动改游戏工程。
- 调用 `inspect` 检查候选配置，展示清档绝对路径和范围：删除该服务器根目录下的整个 `db` 目录及全部内容。确认“清档”和“清档重启”的固定语义，不再询问清档后是否启动。
- `inspect` 会列出启动脚本自带的目录删除、配置重建、安装程序调用和全局 EPMD 关闭行为。把具体绝对路径和影响纳入一次配置确认；已经在会话中明确确认的内容直接复用，只问缺项。脚本格式未知时报告需要适配，不猜关闭方式或随意改启动脚本。
- Codex 根据目标项目配置和只读检查确定业务监听端口，填入 `required_ports`。动态 Erlang 分发端口不能当固定业务端口；缺少可靠依据时只问必要端口。正常关闭使用目标目录的 `erl_call`，对唯一的目标节点调用 `init:stop/0`，并确认进程及节点登记退出。
- 将 `inspect` 返回的 `profile` 保存到技能目录内的临时配置草案，调用 `configure --profile-file "<草案绝对路径>" --confirmed`；`--confirmed` 代表用户已在对话中确认配置，不是执行授权。配置完成后清理该草案。正式状态保存在本技能目录 `state`，分发 ZIP 不携带状态。
- `ready`：简短说明绑定目标，直接接收任务。配置与业务状态不同；操作前仍实时核验。`needs_reconfirmation`：只重新确认失效或变更项，保留用户同句话中的待执行任务。不要自动切换到其他服务器。

## 指令语义

| 用户意图 | operation | 执行顺序 |
|---|---|---|
| 查看状态 | status | 查询绑定 Unity 的 Play 状态、目标服务器进程与端口 |
| 开启 | start | 已健康运行则复用；已停止才执行启动 BAT 并验证 |
| 关闭 | stop | 正常关闭目标节点并确认退出 |
| 重启 | restart | 正常停服并确认退出 → 启动 BAT → 验证，保留 db |
| 清档／清理存档 | clear | 确认退出 Unity Play → 正常停服并确认退出 → 删除整个 db，保持停服 |
| 清档重启／重置服务器 | clear-restart | 完成清档 → 启动 BAT → 验证 |

两种清档操作结束后 Unity 保持未 Play，不自动开始游戏。暂停 Play 不等于退出 Play。关闭启动脚本窗口不等于关闭实际服务器，必须验证目标进程退出。单独说“清理”而没有明确清理对象时，澄清是否指清档；不要把普通重启转换为清档。

## 下达任务与反馈

目标和操作明确且已有用户授权时，调用 `plan OPERATION`，核对目标、步骤和启动副作用后，直接调用 `execute ID --yes`；无需重复询问已授权的正常操作。配置确认、打包请求、预检请求都不是实际清档授权。

同一句可以同时指定服务器与任务，完成配置后继续原任务。用户明确切换服务器才重新绑定；临时提到另一个目录不改变默认目标。

执行脚本持有配置锁和当前 Windows 用户下按服务器目录隔离的互斥锁。不要复制状态或另起进程规避锁。一次只提交一次；中断、超时或 `outcome_unknown` 时先 `result ID` 和 `status`，需要关闭未知记录时按 [references/usage.md](references/usage.md) 核查，不自动重试清档。

用户反馈包含目标、操作、完成步骤、最终状态和操作编号。`prepared` 仅表示预检；`completed` 才表示本工具的进程／节点／端口条件通过，不能声称游戏业务登录已验证。脚本无法确认 Unity、遇到目录链接、多个同名节点、启动文件变化、其他实例共用 EPMD 或正常关闭失败时，说明具体阻断点；不扩大删除范围或自动强杀。

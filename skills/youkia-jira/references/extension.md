# 未列出功能的发现

功能目录是已封装入口，不是对 Jira 的最终能力判定。先把新请求拆成目标资源和读写性质，选择与需求直接相关的只读探测，不全站扫接口。

用 `api-read` 探索本站 `/rest/api/2/` 或 `/rest/agile/1.0/` 资源，例如项目版本、组件、当前用户权限、用户搜索、看板或 sprint。只调用合理的读取端点；端点以 GET 命名不保证没有副作用，含执行/触发语义时先确认。插件接口不在通用入口范围，需查对应插件官方文档与实际站点支持情况再实现。

核心字段或流转新增功能优先复用 `meta` 与现有 `fields/update` 请求。若需新写接口，先根据用户需求实现可审核的专用入口、目标校验、参数验证和结果回读，再执行已授权动作；不能借“探索”发试探性创建或更改权限。

401 重新登录；403 说明当前权限/额外验证；404 区分资源不可见和版本不支持，结合相邻元数据再判断；网络错误不代表功能不存在。不要绕过登录验证码、SSO、权限或管理员限制。

适配新网站时保留真实认证方式差异。Server PAT 与 Cloud API Token 不是同一种认证；当前包优先面向已验证的 Jira Server 9.4，不承诺所有 Cloud、插件和 SSO 组合开箱即用。

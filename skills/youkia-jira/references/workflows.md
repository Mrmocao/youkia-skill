# Bug、优化与验收

“解决”“关闭”“验收通过”“重开”是业务意图，不是跨项目通用状态 ID。每次读取任务类型、当前状态及 `meta transitions`，用实际可用转换和必填字段完成。不要固定默认项目或保存工作流映射。

提交 Bug：先确定项目及父任务/版本范围，发现可创建类型和字段，整理摘要、复现步骤、预期/实际、环境与附件。缺少实际必填值时集中询问，已有信息直接用；用户授权提交后创建并回读。

解决 Bug：读取当前可用流转。修复原因、解决方案、解决版本等可能只出现在流转字段，不能只看编辑元数据后误判不可填写。`resolution` 是解决结果枚举，不是解决方案长文本。先填授权的业务内容，再流转并回读目标状态和字段。

待验收查询：按当前缺陷工作流解释。对于“已解决 → 关闭”流程，已解决任务可能包含已修复、不解决、重复等结果；分组呈现，别把所有已解决任务算作待验证的修复。普通任务存在“验收通过”不表示缺陷也有该状态。使用 `pending-bugs` 后必须带上其解释和解决结果分组；要仅看实际修复时再按本项目当前 resolution 过滤。

验收与重开：列任务不构成验收证据。用户提供测试结论或明确授权业务状态变更后，读取当前流转并执行；不要自行声称测试通过，不自动启动游戏、Unity 或 GM。找不到所需流转时说明当前状态、可用动作和权限边界。

优化事项：使用该项目可创建的优化类型或用户指定任务类型；沿其真实工作流，不能把优化当缺陷强制套用字段。

对话里已明确的目标、字段和授权继续有效，通常无需重复逐项确认；任务状态变化导致原操作含义变化时才重新澄清。
